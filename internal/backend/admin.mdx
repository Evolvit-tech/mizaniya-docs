`Mizaniya-Pay-Admin-POS-Backend` serves the admin web app only. Same stack as the POS backend: NestJS 11, TypeORM, Postgres, Redis.

**It never calls the POS API.** Both write to the same database through the [shared database](/backend/shared-database). An admin change (a price, a suspension, a top-up) is a row the POS side reads on its next request.

## Login

An admin logs in in two steps. Every route except those marked `@Public()` needs a valid access token (global `JwtAuthGuard`).

<Steps>
  <Step title="Password">
    `POST /auth/check-credentials` checks the email and password and emails a 6-digit code.
  </Step>
  <Step title="Email code">
    `POST /auth/check-otp` checks the code and returns the access and refresh tokens. `POST /auth/resend-otp` sends a new code.
  </Step>
</Steps>

**Refresh:** `POST /auth/refresh`. **Forgotten password:** `POST /auth/forgot-password`, then `/forgot-password/verify` with the emailed code, then `/forgot-password/reset`.

**Outside `production` the code is always `000000`** (`src/common/utils/generate-otp.util.ts`, since `482335f`). It is still emailed unless `MAIL_DISABLED=true`, which logs emails instead of sending them and is refused in production.

**The super admin** is created by the shared-database migration `manual-MGSuperAdmin`, with the password from `SAPWD`.

## Settings shared with the POS side

The admin backend **shows** prices and margins; the POS backend **charges** them. These variables must have the same value in both deployments:

`COMMISSION_ENGINE_ENABLED`, `GIFT_CARD_COST_PLUS_ENABLED`, `GIFT_CARD_MARKUP_PERCENT`, `GIFT_CARD_SERVICE_FEE_DZD`, `ESIM_COST_PLUS_ENABLED`, `ESIM_MARKUP_PERCENT`.

Several other settings use **different names** than in the POS backend, for example `SAPWD` and `CORS_ORIGINS`. See [Environment variables](/environment#admin-backend).

## Background job

One `@Cron`: the daily expiry and deletion of admin reset keys (`src/common/token-keys/token-keys.service.ts`, 01:00).

## Run it

```bash
npm ci
npm run start:dev          # watch mode
npm run build && npm run start:prod
```

Tests use **Jest**, not Vitest like the POS backend: `npm test` and `npm run test:e2e`. See [Testing](/workflows/testing).

### All scripts

| Script | What it does |
| --- | --- |
| `start`, `start:dev`, `start:debug` | Run from source; `start:dev` watches, `start:debug` also opens the debugger |
| `build`, `start:prod` | Compile to `dist/`, then run `node dist/src/main` |
| `lint`, `format` | ESLint with `--fix`, Prettier on `src/` and `test/` |
| `test`, `test:watch`, `test:cov`, `test:debug` | Jest unit tests: once, watching, with coverage, with the debugger |
| `test:e2e` | End-to-end suite against `.env.test`; see [Testing](/workflows/testing) |
| `typeorm` | The TypeORM CLI against `.env` |
| `migration:new`, `migration:generate` and their `-win` variants | Create a migration in the shared database; see [Shared database](/backend/shared-database#migration-scripts) |
| `migration:run`, `migration:show`, `migration:revert` | Run, list or revert migrations against `.env` |
| `migration:run-test`, `migration:show-test`, `migration:revert-test` | The same against `.env.test` |
| `prepare` | Install the husky git hooks; runs on `npm ci` |

The admin backend has no seed script. The only seed runner is the POS backend's (`npm run seed`), on the database both APIs share.
