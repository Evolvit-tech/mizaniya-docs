---
title: "Environment variables"
description: "Every variable each app reads, what it does, and whether you must set it."
---

Each backend validates its environment at startup with a zod schema, `src/common/config/environment.validation.ts`. A missing required variable stops the app with `Environment validation failed:` and the variable's name.

**Required** means the app does not start without it. **Default** is the value used when the variable is unset.

**Fake values for every required variable**, ready to run locally, are in the local kit: `local-dev-kit/env/pos.env.example` and `local-dev-kit/env/admin.env.example`.

<Warning>
  Never paste a real value into this page, a PR or a chat. Every example here is fake. For local work, the [local kit](/local-setup) generates working fake values.
</Warning>

<Note>
  This page follows the `staging` branch. When you add or change a variable, update the schema, the repository's `.env.sample`, and this page in the same PR.
</Note>

## POS backend

### Runtime

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `NODE_ENV` | No | `dev` | `production` turns on the Swagger login, real phone codes and the production-only checks |
| `PORT` | No | `3001` | HTTP port |
| `CONFIGS_API_BASE_URL` | No | `http://localhost:3000` | Public address of this API |
| `CONFIGS_CORS_ORIGINS` | No | none, see below | Comma-separated web origins allowed to call the API |
| `TRUST_PROXY_HOPS` | No | `0` | Number of reverse proxies in front of the app; staging uses `2` |
| `CONFIGS_LAST_ACTIVE_THRESHOLD_BY_DAYS` | No | `30` | Days without activity before an account counts as inactive |
| `SWAGGER_USER` | In production | none | Login for `/api`, `/api-json` and `/reference` |
| `SWAGGER_PASS` | In production | none | Password for the same routes |

<Warning>
  `main.ts` reads `CONFIGS_CORS_ORIGINS` straight from the process, so the schema's default never applies. **If it is unset, no browser origin is allowed** and the web app cannot call the API.
</Warning>

### Database and Redis

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `DB_HOST` | No | `localhost` | Postgres host |
| `DB_PORT` | No | `5432` | Postgres port |
| `DB_USERNAME` | Yes | none | Postgres user |
| `DB_PASSWORD` | Yes | none | Postgres password |
| `DB_NAME` | Yes | none | Database name |
| `REDIS_HOST` | Yes, not validated | none | Redis host |
| `REDIS_PORT` | Yes, not validated | none | Redis port |
| `REDIS_USERNAME` | No | empty | Redis user |
| `REDIS_PASSWORD` | Yes, not validated | none | Redis password |

The `REDIS_*` variables are read outside the schema (`src/common/redis-store/redis-store.ts`). A missing one fails at the first cache call, not at startup.

## Admin backend

The admin backend uses **different names** for some of the same settings. Copying a POS `.env` does not work.

| POS backend | Admin backend |
| --- | --- |
| `CONFIGS_SAPWD` | `SAPWD` |
| `CONFIGS_API_BASE_URL` | `API_BASE_URL` |
| `CONFIGS_CORS_ORIGINS` | `CORS_ORIGINS` |
| `AWS_STORAGE_MASTER_KEY` | `STORAGE_MASTER_KEY` |
| `AWS_STORAGE_MASTER_KEY_SALT` | `STORAGE_MASTER_KEY_SALT` |
| `JWT_ACCESS_TOKEN_EXPIRY` | `ACCESS_TOKEN_EXPIRY` |
| `JWT_REFRESH_TOKEN_EXPIRY` | `REFRESH_TOKEN_EXPIRY` |
| `JWT_PASSWORD_RESET_TOKEN_EXPIRY` | `PASSWORD_RESET_TOKEN_EXPIRY` |

### Same as the POS backend

These work exactly as in the POS backend tables above:

- **Runtime:** `NODE_ENV`, `PORT`, `CONFIGS_LAST_ACTIVE_THRESHOLD_BY_DAYS`, `SWAGGER_USER`, `SWAGGER_PASS`.
- **Database and Redis:** every `DB_*` and `REDIS_*` variable.
- **Tokens:** `JWT_AT_SECRET`, `JWT_RT_SECRET`, `JWT_EMAIL_VERIFY_TOKEN_EXPIRY`, `CONFIGS_EMAIL_VERIFY_URL`.
- **Email:** `EMAIL_HOST`, `EMAIL_USERNAME`, `EMAIL_PASSWORD`, `MAIL_DISABLED`, `OTP_EXPIRATION_DURATION`.
- **Storage:** every `AWS_*` variable except the master key pair (renamed above).
- **Static QR:** `STATIC_QR_BASE_URL`, `STATIC_QR_API_KEY`.

`CORS_ORIGINS` has the same trap as the POS one: unset means no origin is allowed.

`REDIS_USERNAME` has no empty fallback in the admin backend: if it is unset, the Redis URL holds the word `undefined` as the user. Set it, even to an empty value.

| `STORAGE_MASTER_KEY` | Yes | none | Key that encrypts stored files |

### Must match the POS backend

The admin backend only **shows** prices and margins; the POS backend **charges** them. Set these to the same values in both, or the admin team sees prices nobody pays:

| Variable | Default |
| --- | --- |
| `COMMISSION_ENGINE_ENABLED` | `false` |
| `GIFT_CARD_COST_PLUS_ENABLED` | `false` |
| `GIFT_CARD_MARKUP_PERCENT` | `5` |
| `GIFT_CARD_SERVICE_FEE_DZD` | `0` |
| `ESIM_COST_PLUS_ENABLED` | `false` |
| `ESIM_MARKUP_PERCENT` | `0` |
